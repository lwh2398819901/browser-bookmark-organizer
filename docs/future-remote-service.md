# 未来方向：可选的远端智能服务

> 状态：仅作为后续可能方向记录，不属于当前版本的实现范围、安装要求或功能承诺。

## 当前决策

当前版本只做本地使用方案，继续采用以下分工：

```text
用户与本机 Agent 对话
        ↓
Agent 加载 bookmark-organizer 技能
        ↓
命令完成审计，Agent 完成语义判断并生成方案
        ↓
本地浏览器扩展负责备份、校验和执行
```

当前版本不建设远端账号系统、任务服务、Agent 集群、云端数据存储或在线计费，也不要求插件连接任何远端服务。插件不存储模型 API 密钥，不上传收藏夹数据。

## 为什么保留这个方向

如果未来面向没有本机 Agent 的普通用户，远端服务可以让用户只安装浏览器插件，并直接在插件页面发起整理、检查和画像任务。服务器统一配置 Agent、技能和网页分析能力，可以避免逐一适配用户电脑上的 Codex、Claude Code、Cursor 等工具。

只有出现以下需求时，才重新评估远端模式：

- 面向大量非技术用户发布；
- 希望用户不安装或不打开本机 Agent；
- 希望插件页面成为完整的智能交互入口；
- 能承担持续的服务器、模型、认证和运维成本；
- 已经确定收藏夹数据的隐私政策、保留期限和用户删除机制。

仅为了减少当前流程中的少量复制粘贴，不足以启动远端架构。

## 候选架构

```text
浏览器插件
   │
   │ HTTPS：提交任务、接收进度和整理方案
   ↓
远端收藏夹服务
   ├─ 用户认证与设备绑定
   ├─ 任务调度与隔离工作区
   ├─ Agent 运行环境
   ├─ bookmark-organizer 技能
   ├─ 网页内容提取与链接检查
   └─ 结构化方案校验
   │
   ↓
插件展示方案并等待用户确认
   ↓
插件在本地备份、重新校验并调用浏览器 API
```

服务器只能返回建议和结构化计划，不能直接获得浏览器写权限。真实书签 ID、完整归档和最终改动继续留在插件本地。

## 数据最小化

远端模式仍应遵守“本地完成确定性工作，远端只处理必要语义”的原则。

默认留在本地：

- 完整收藏夹 HTML 归档；
- 浏览器运行时书签 ID；
- URL 精确重复检查；
- 方案执行前校验；
- 创建目录、移动、删除和恢复操作；
- 最近 30 份归档的维护。

按任务和用户授权发送：

- 当前待整理条目的标题、网址和原目录；
- 可选的现有目录结构与少量代表样本；
- 用户本次提出的分类偏好；
- 深度画像所需的受控证据摘要；
- 无法仅凭摘要判断时所需的公开网页内容。

整理少量临时收藏时，不应默认上传整个收藏夹。内部网站、登录页面和用户明确标记为私密的内容不得发送远端。

## 接口边界

候选服务只需要稳定的任务接口，不向插件下发可执行代码：

```text
POST /v1/tasks
GET  /v1/tasks/{taskId}
GET  /v1/tasks/{taskId}/events
POST /v1/tasks/{taskId}/message
POST /v1/tasks/{taskId}/cancel
GET  /v1/tasks/{taskId}/result
```

候选任务类型包括：

- `organize_temporary`
- `organize_all`
- `check_links`
- `analyze_duplicates`
- `generate_profile`
- `revise_plan`

服务端结果必须满足版本化 JSON Schema。插件只接受明确支持的动作类型；未知字段忽略，未知动作拒绝。服务端使用任务临时编号，插件在本地映射并重新验证真实书签 ID。

## 安全与隐私前提

远端方向开始实施前，至少要确定：

- 全程 HTTPS，限制插件可连接的服务来源；
- 账号、设备绑定、令牌撤销和异常登录处理；
- 每个 Agent 任务运行在隔离且有时限的工作区；
- 网页内容始终作为不可信数据，不能覆盖系统和技能规则；
- 默认最短数据保留，并提供查看、导出和立即删除机制；
- 服务器日志不得记录完整收藏夹、访问令牌或模型密钥；
- 移动前必须由插件重新扫描并创建本地归档；
- 删除、清空和批量替换继续要求单独确认；
- 服务不可用时，本地备份、扫描和执行已有方案仍可使用。

## 与本地版本兼容

如果未来增加远端模式，不应替换当前本地流程。两种模式应共用：

- 审计结果格式；
- 整理方案 JSON Schema；
- 动态分类和授权规则；
- 插件预检、归档和执行器；
- 结果验证与错误报告。

建议把远端能力设计为可选连接：默认保持本地模式，用户主动配置服务器并授权相应数据范围后才启用。

## 启动实现前的决策门

满足以下条件后，才把本文档转化为开发计划：

1. 明确目标用户是个人自托管还是公共服务。
2. 确定 Agent 运行时、模型供应方式和费用承担方式。
3. 确定数据保留、隐私声明和账号删除流程。
4. 完成威胁建模与整理方案 Schema 的版本设计。
5. 用匿名样本验证远端模式相较本地流程确实显著降低操作成本。

在这些条件满足前，维护重点仍是改进本地审计、技能判断、插件预览和安全执行体验。
