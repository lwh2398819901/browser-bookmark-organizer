# 意图理解与授权边界

## 触发词不是白名单

先理解用户要处理的范围、期待结果和当前对话上下文，再选择合适的工作方式。下表只是常见表达的提示，而不是只有说出这些词才会工作。

| 用户可能的说法 | 通常代表的意图 | 建议的默认动作 |
|---|---|---|
| 备份我的收藏夹、先归档一下、导出一份当前书签、什么都别改只留个备份 | 仅备份 | 生成完整可导入 HTML；不审计、不整理、不改动 |
| 收藏当前网页、先放进临时收藏、这个网页存一下 | 快速收藏 | 使用扩展工具栏检查全库重复后加入 `临时收藏` |
| 这些书签太乱了、帮我归一归、第一次收拾一下 | 全量整理 | 先审计并提出方案 |
| 把刚存的处理掉、收件箱里这些该去哪、待整理的归类一下 | 临时收件箱归档 | 调用本地桥接实时扫描，生成并校验计划；用户确认预览后自动执行 |
| 有没有重复、这些是不是保存过、相似链接合并一下 | 重复检查 | 区分精确重复与关联参考 |
| 看看哪些过期了、这些网站还活着吗、有没有改版 | 链接健康 | 检查可用性、标题和重定向变化 |
| 我都在关注什么、帮我看看知识结构、画像 | 收藏夹画像 | 输出事实层和 AI 语义层 |
| 就按你说的放、把这些归到某目录、现在动手 | 应用计划 | 重新预检后执行明确范围内的移动 |
| 撤销上次整理、刚才放错了、把这批放回去 | 撤销整理 | 先备份当前状态，再按插件操作记录移回原目录 |
| 恢复收藏夹、从某天的备份找回来 | HTML 恢复 | 展示备份文件并使用浏览器原生导入；说明导入会合并 |

用户也可能只说“这些”“刚才那批”“放回原来的地方”。应优先利用当前会话中已展示的条目、计划和目录；只有范围或目标会导致实质不同结果时，才提出一个简短澄清问题。

## 按风险理解授权

- “备份”“归档”“导出一份”只授权创建备份文件，不授权整理、移动、删除、清空或替换；除非用户在同一请求中明确要求后续操作。
- “先备份再整理”授权先创建备份，但整理部分仍按对应范围和风险进行预检；备份失败时不得继续改动。
- 用户明确说出条目范围与目标目录时，例如“把临时收藏里的 Git 教程放到 Linux/课程与学习”，可在预检后移动，不要求出现固定的“执行”二字。
- 用户只说“整理一下”“先看看”时，先识别其指向全库还是临时收藏：全库才运行审计，临时收藏使用扩展实时扫描；范围仍不明确时只澄清或给非执行建议，不改动收藏夹。
- 用户对刚展示的计划说“可以”“按这个来”“其余删除”，可视为对该计划范围的确认；范围之外不外推。
- 删除书签、清空收藏夹和批量替换必须有明确对象或已展示清单上的明确确认。插件页面中“删除备份”“清空记录”等指向单一明确对象的按钮点击本身即为授权，不再要求第二次弹窗确认。
- “恢复收藏夹”不自动授权清空当前收藏夹。优先区分“撤销插件移动”和“从 HTML 备份导入”；前者按操作记录移回，后者使用浏览器原生导入并提示合并风险。
- 失效、超时、登录限制和反爬结果始终只是复核信号，不能单独构成删除授权。
