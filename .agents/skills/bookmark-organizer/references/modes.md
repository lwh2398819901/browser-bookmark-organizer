# 运行模式详解

模式用于理解任务，不是只能由固定命令触发的开关。优先依据用户语境、处理范围、期待结果和风险等级判断，并选择足以完成任务的最轻数据源；以下只是常见情形。

## 快速收藏

用户要保存当前打开的 HTTP(S) 网页时，优先使用扩展工具栏的“加入临时收藏”。扩展会先与全库规范化网址比较：主机大小写、默认端口、查询参数顺序和常见跟踪参数差异可以归并；不同 URL 片段继续作为不同章节保留。已有相同网址时只展示原目录，不创建重复收藏。

## 仅备份收藏夹

用户只要求“备份”“归档”“导出一份”或表达等价意图时，创建当前收藏夹的完整、可重新导入 HTML，不附带审计、分类、去重、链接检查或任何收藏夹改动。

1. 优先调用 `python scripts/bookmarkctl.py --pretty backup`。命令通过配套扩展生成备份，不要求用户打开插件页面。桥接不可用时，才使用工具栏“立即备份”、整理中心“一键备份收藏夹”或浏览器原生导出功能。
2. 不得为触发自动归档而构造空移动计划，也不得把审计报告或 Chromium `Bookmarks` 数据文件称为可导入备份。
3. 成功后报告备份文件的完整路径、生成时间；可可靠取得时再报告书签数、文件夹数和文件大小，并明确说明“本次没有修改收藏夹”。
4. 单独备份沿用专属归档目录和最近 30 份保留目标；如果当前执行方式无法安全自动清理旧归档，应说明这一点，不得擅自删除普通下载文件或来源不明的 HTML。用户点击备份列表中明确的“删除备份”按钮后直接删除该备份文件，不再二次弹窗。
5. 用户同时要求“先备份再整理”时，将备份作为整理前置步骤；归档失败即停止后续改动。

## 恢复与撤销

先判断用户要撤销插件刚执行的移动，还是从历史 HTML 恢复整个收藏夹。

- 插件整理记录仍在时，先用 `bookmarkctl.py --pretty operations` 查看记录；已有明确撤销授权时运行 `bookmarkctl.py --pretty undo --operation-id <id> --confirmed`。扩展会先备份撤销前状态，再按记录把书签移回原父目录、原索引和原有顺序；不会删除整理时创建的空文件夹。
- 从 HTML 深度恢复时，在整理中心按日期找到备份、显示文件，再使用浏览器原生“导入收藏夹/书签”。导入通常与当前收藏夹合并，不能把它描述成覆盖式回滚。
- 不得为了制造“完全恢复”的效果而自动清空当前收藏夹。若用户确实要求替换整个收藏夹，必须单独确认具体数据范围并使用浏览器支持的流程。

## 首次全量整理

1. 获取浏览器 HTML 导出，或复制 Chromium 的 `Bookmarks` 文件；始终保留输入文件不变。
2. 不加 `--check-links` 先审计，查看精确重复、目录分布、域名分布和异常 URL。
3. 用户需要检查链接时，再单独运行链接检查。非 2xx 不能单独证明书签应该删除：登录限制、限流和反爬都很常见。
4. 仅对现有目录、标题、域名和审计报告无法判断归属的条目阅读网页。已有的合理组合应被视为线索，而不是随意打散。
5. 用户只要求“先看看”时停在建议阶段；用户明确指定范围、目标目录和改动意图时，可在预检后移动。离线重组尚未提供正式工具；实时浏览器整理使用收藏夹 API。通过本地扩展移动时，扩展必须先生成完整 HTML 归档，归档成功后才可继续。
6. `audit.json` 和 `ai-profile-brief.md` 已提供目录、重复关系和代表样本时直接复用；只有缺少完成当前判断所需的数据时才补充命令，不重写临时解析器重复生成同类字段。

## 临时收藏归档

`临时收藏`通常是收件箱，而不是固定分类；用户也可能叫它“收集箱”“待整理”或“先放这里”。当前实现仅识别名为 `临时收藏` 的目录；其他名称的收件箱尚未提供配置能力，不能假定默认扫描覆盖它。

1. 调用 `bookmarkctl.py --pretty scan` 重新扫描目标收件箱；不运行全量审计，也不要求用户操作插件页面。
   > Windows 上由 Agent 代跑命令时，优先使用 `--output <临时目录>\scan.json` 落盘读取。`--output`、`--pretty` 可写在子命令之前或之后。若只能使用控制台或管道，先按[本地执行扩展](local-extension.md)的“Windows 命令行环境的输出与编码”设置编码。
2. 命令返回的实时 ID、全库精确重复路径和现有目录是本次计划的数据来源。桥接失败时先诊断安装与连接，不得回退到离线文件获取 ID 或视觉自动化。
3. 若其他位置已有相同 URL，报告现有路径。不同 URL 片段通常表示章节或标题，属于关联参考而非重复；精确重复不会被自动删除。
4. 对剩余条目按需读取内容，优先复用稳定目录；仅在没有长期合适分类时创建窄而清晰的新目录。
5. Agent 可以原样使用命令返回的 ID，但不得从 Chromium `Bookmarks`、HTML 导出或自建脚本获取执行 ID。移动方案是 `[{"id":"...","folderPath":"..."}]`，软删除是 `[{"id":"...","action":"delete"}]`，不额外生成 HTML。
6. 用 `validate-plan` 获取逐条预览和短时令牌。用户已明确范围、目标目录和移动意图且预览未扩大授权时，可用 `apply-plan --confirmed` 执行；否则先展示预览取得确认。完成后读取执行器逐项结果及 `verified`；全库模式按目标目录核验。
7. 正常流程使用 `scan`、`validate-plan`、`apply-plan`；执行器内部核验移动结果，额外扫描仅用于异常或结果不确定。不要在 `apply-plan` 前调用 `backup`，因为执行命令已经强制先归档；不要把 `status`、`archives` 或 `operations` 加入固定流程。命令输出不确定时先核对真实状态，不要盲目重试。
8. 完成后重新扫描收件箱时，若出现不在已确认计划内的新条目（用户可能在整理期间又收藏了网页），只报告条目和建议去向，等用户确认后单独走一次 `validate-plan` → `apply-plan`；不得并入上一次已确认的计划。

## 收藏夹画像与变化检测

HTML 画像应描述收藏夹本身，不应从书签证据外推私人或敏感特质。它可以展示：

- 收藏、目录、高频目录和高频域名；
- 从已有目录和内容线索得到的结构分布；
- 精确重复与关联 URL 组；
- 链接检查结果，包括“无法确认”；
- 与先前审计相比的重定向、标题和可用性变化。

需要深度语义画像时，使用审计生成的 `ai-profile-brief.md`。AI 应从当前用户的目录、标题、来源和样本动态归纳主题，而不是套用预设分类；输出 `ai-insights.json` 后使用 `--ai-insights` 重新生成报告。必须清楚区分命令生成的事实和 AI 解读。

将此前的 `audit.json` 作为 `--baseline`，可标记重定向、标题或链接状态发生的变化；该参数会自动启用当前链接检查。标题或重定向变化只是复核信号，不等于内容过期。HTML 导出没有浏览器运行时 ID，不能直接生成供扩展执行的计划；实时移动前必须由配套扩展重新扫描。

## 删除与目录维护

用户点名要删除的书签，先用 `action: "delete"` 做软删除预览，目标是收藏夹栏下的 `回收站`。用户明确说永久删除、清空、不保留时，才使用 `validate-plan --purge` 或 `purge-recycle`。链接检查里的失效、超时和登录页本身不是删除授权。

空目录用 `prune-folders --empty` 预览。父目录下面只剩空壳时加 `--recursive`。非空目录要写出书签数量；没有 `--purge` 时整棵移入回收站。目录改名和排序使用 `rename-folder` 与 `move-folder`，同样先预览。`临时收藏` 和 `回收站` 不能被这些命令改名、移走或清掉。

撤销永久删除会重建书签或目录，新的运行时 ID 不能写回旧计划。软删除撤销仍使用原来的 ID。
